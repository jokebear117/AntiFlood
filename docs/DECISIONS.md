# Anti-Flood — 의사결정 기록

- **상태:** 2단계 의사결정 정리 완료 (논리 아키텍처 확정)
- **기준일:** 2026-11-24
- **관련 문서:** [ARCHITECTURE.md](./ARCHITECTURE.md)
- **목적:** 구현 중 설계 결정을 반복하지 않도록 확정 사항, 핵심 기술 의존성, 일반 구현 세부사항을 구분한다.

> **개발 원칙:** 작동하는 서울 침수 상태 갱신 시스템을 만드는 데 집중한다. 별도의 성능 실험·평가 플랫폼이나 검증을 위한 검증 작업을 만들지 않는다. 다만 시스템 구동을 막는 기술 의존성과 물리 계산의 기본 정합성은 확인한다.

## 1. 확정된 결정

| ID | 결정 | 이유 |
|---|---|---|
| D-01 | **4계층 아키텍처:** Data Layer → Stream Processor → Flood Simulation Engine → Visualization | 역할을 구분하되 시스템 구조를 최소화한다. |
| D-02 | **단일 2D Cellular Automata(CA) 침수 계산 모델**을 사용한다. | 물리 엔진 간 정밀도 비교가 아닌 시공간 데이터 처리에 집중한다. |
| D-03 | **외부에 공개된 기존 침수 계산 코드를 우선 재사용**한다. | 물리 계산 엔진을 처음부터 개발하지 않는다. **사용자의 로컬에 이미 존재하는 코드를 뜻하지 않는다.** |
| D-04 | 공개 코드 후보는 **CADDIES/CAFLOOD WCA2D**를 1순위로 검토한다. | 격자 기반 침수 계산과 CPU 병렬 실행을 고려한 후보이며, **최종 채택이 확정된 것은 아니다.** |
| D-05 | **100m × 100m Tile**을 활성화·작업 관리 단위로 사용한다. | 지역별 계산 대상을 단순하게 관리한다. Tile 하나마다 별도 프로세스를 만들지는 않는다. |
| D-06 | 물리 계산은 **확보한 약 30m DEM 해상도**를 기본으로 한다. | 원본보다 세밀한 지형 정보가 존재하는 것처럼 가정하지 않는다. Tile 경계와 물리 격자 경계는 구분한다. |
| D-07 | 집중호우 때 관련 Tile을 활성화한다. **기존 수심·인접 Tile의 유입 가능성도** 활성화 조건에 포함한다. | 강우가 없는 곳에도 물이 이동할 수 있다. |
| D-08 | 기존 강우 시계열을 **시간순으로 재생**하여 스트림 입력을 구현한다. | 실시간 외부 API 없이 일관된 입력을 제공한다. |
| D-09 | 지역별 최근 강우 정보는 **Sliding Window / 지수 감쇠 요약**을 활용해 관리한다. | 강의 4주차 스트림 처리 개념을 계산 대상 선택에 활용한다. |
| D-10 | 우선순위 결정은 **엔진 내부의 간단한 온라인 스케줄링 규칙**으로 구현한다. | 별도 큐 서비스나 스케줄링 서버를 두지 않는다. |
| D-11 | **노트북 CPU 기반 병렬 처리**를 채택한다. 기본 방향은 기존 엔진의 **OpenMP** 활용이다. | 내장 GPU나 다중 노드 클러스터 없이 실행한다. 실제 병렬화 API는 선택된 공개 코드의 지원 범위에 따른다. |
| D-12 | 물리 계산은 **하나의 연속된 수심 상태**를 공유하며, 인접 격자 사이 물 이동과 경계 정합성을 유지한다. | Tile 분할 때문에 물의 흐름이 끊기지 않도록 한다. |
| D-13 | **서울 3D 지형 위에 수심 레이어**를 표시하고 시간에 따른 변화를 재생한다. | 지도는 결과를 표현하며, 유체 계산 자체를 수행하지 않는다. |
| D-14 | 초기 기술 스택은 **Python, NumPy, Rasterio, FastAPI, HTML/Vanilla JS, MapLibre GL JS**로 한다. CA 엔진은 재사용 코드의 언어·빌드 방식을 따른다. | 작고 로컬에서 실행 가능한 구성을 유지한다. |
| D-15 | **Upstage Solar 기반 LLM 에이전트**는 읽기 전용 상태 조회·설명 보조 기능으로 분리한다. | 강의 프로젝트 요구사항을 고려하되 물리 계산은 AI에 위임하지 않는다. |
| D-16 | **별도 실험·평가 시스템을 구축하지 않는다.** | 우선순위는 동작하는 전체 파이프라인 완성이다. |
| D-17 | **물리 계산 시간 간격**과 **화면/결과 갱신 주기**를 구분한다. | 결과 표시 주기를 조절했다고 계산량 자체가 줄었다고 주장하지 않는다. |

## 2. 핵심 기술 의존성 — 구현 전에 반드시 확인할 2가지

이 두 항목은 연구를 위한 추가 실험이 아니라, **시스템의 핵심 기능을 기존 공개 코드로 구현할 수 있는지 확인하는 작업**이다. 별도의 검증 프로젝트를 만들지 않고 실제 개발 착수 과정에서 코드와 최소 실행 경로를 확인한다.

| ID | 반드시 가능한 동작 | 확인해야 하는 이유 | 불가능할 때의 처리 |
|---|---|---|---|
| **T-01** | 기존 수심·유량 상태를 유지하면서 다음 강우 구간을 입력하고 **연속 계산**할 수 있어야 한다. | 이것이 불가능하면 강우 스트림에 따라 침수 상태를 계속 갱신하는 파이프라인이 성립하지 않는다. | 재사용 코드에 필요한 최소 연동 기능을 추가하거나 다른 공개 CA 구현으로 교체한다. |
| **T-02** | 활성 Tile/격자에 한정해 **실제 수심 계산 연산을 선택적으로 수행**할 수 있어야 한다. | 화면 갱신만 건너뛰는 것으로는 적응형 계산이 구현되지 않는다. | 계산 루프를 최소 수정하거나 활성 영역 제어가 가능한 구현으로 교체한다. |

**공개 코드 채택 시 필수 확인:** 라이선스에 따른 사용·수정·배포 가능 여부, 필요한 소스와 빌드 방법의 제공 여부. 이는 성능 평가가 아니라 코드를 적법하고 안정적으로 프로젝트에 포함하기 위한 기본 절차다.

**엔진 선정 원칙:** WCA2D라는 이름에 종속되지 않는다. 두 핵심 기능을 구현하기 위해 대규모 재작성이나 과도한 우회가 필요하다면 다른 공개 CA 코드를 선택한다. 단일 CA 모델 및 4계층 아키텍처는 유지한다.

## 3. 일반 구현 세부사항 — 개발하면서 결정할 4가지

다음은 별도의 사전 검증 과제가 아니다. 개발 명세서에 기본 방침을 쓰고, 해당 모듈을 구현하면서 구체화한다.

| ID | 항목 | 기본 처리 원칙 |
|---|---|---|
| **I-01** | 활성화 임계값과 강우·수심별 결과 갱신 정책 | 입력 강우 자료의 실제 시간 간격에 맞춰 단순한 초기값을 정한다. 지나친 파라미터 튜닝은 하지 않는다. |
| **I-02** | 배수능력 데이터의 단위와 공간 적용 범위 | 확보한 실제 자료를 우선 사용한다. 없는 지역은 명시된 가정값으로 처리하며 실제 관측값과 구분한다. |
| **I-03** | 지도 지형 데이터와 수심 레이어 형식 | 접근 가능한 공개 데이터로 구현한다. S-MAP의 비공개 내부 기능에 의존하지 않는다. |
| **I-04** | Python과 CA 엔진 사이의 인터페이스 | 선택된 공개 코드가 지원하는 가장 단순한 CLI/파일 또는 라이브러리 연동 방식을 사용한다. |

## 4. 범위에서 제외할 기능

- Landlab과 ANUGA 등을 동시에 실행하는 복수 유체 엔진 비교.
- 3D 유체 역학 전체를 직접 계산하는 고정밀 CFD 시스템.
- 100m Tile마다 별도의 프로세스 또는 독립된 유체 시뮬레이터를 실행하는 구조.
- 동적 물리 격자 세분화(AMR).
- Kafka, Spark 클러스터, Kubernetes, Redis, PostgreSQL 및 클라우드 GPU의 필수 도입.
- 별도의 성능 실험 파이프라인, A/B/C 비교 대시보드, 끝없는 파라미터 튜닝.
- 운영 중 외부 실시간 강우 API 연동, 대피 경로 추천, 시민 알림, 사용자 계정.
- LLM을 이용한 수심 계산·유량 결정.

## 5. 표현과 주장에 관한 기준

| 표현할 수 있는 내용 | 혼동하거나 과장하지 않을 내용 |
|---|---|
| 실제 DEM과 강우·배수 조건을 사용한 **근사 수심 계산** | 실제 서울 전역의 관측 수심을 정확하게 예측한다는 주장 |
| 단일 노트북의 **멀티코어 CPU 병렬 처리** | 여러 물리 노드에서 실행하는 분산 클러스터라는 주장 |
| **100m Tile 단위 작업 관리** | 물리 계산 격자 해상도가 100m라는 주장 |
| 강우·잔류 수심·인접 유입을 고려한 **활성 계산 영역 선택** | 비가 없는 Tile을 무조건 계산에서 제외해도 된다는 주장 |
| 공개 CA 코드를 기반으로 **필요한 부분만 연동·수정** | WCA2D가 모든 필요한 기능을 원래부터 지원한다는 주장 |

물의 질량 보존, 음수 수심 방지, 시간축 정합성은 별도의 연구 실험이 아니라 **기능 구현 시 지켜야 할 기본 정확성 조건**이다.
