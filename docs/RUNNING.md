# 설치와 실행

## 최초 준비

Windows에서는 WSL Ubuntu에서 Python 3.11 이상과 CMake 3.20 이상, OpenMP 지원 C++ 컴파일러를 준비합니다. 지도에는 WebGL 2를 지원하는 브라우저가 필요합니다. 아래 명령은 리포지토리 루트에서 한 번 실행합니다.

```bash
sudo apt update
sudo apt install g++ cmake make python3 python3-venv ca-certificates
python3 -m venv ~/.venvs/antiflood
source ~/.venvs/antiflood/bin/activate
python -m pip install -e .
python -m antiflood.prepare
cmake -S engine -B build/engine-linux -DCMAKE_BUILD_TYPE=Release
cmake --build build/engine-linux
```

준비 명령은 서울시 강우 ZIP, EPSG:5181 관측소 위치, FABDEM의 N37E126·N37E127 타일과 MapLibre 배포 파일을 내려받습니다. 원본 서버가 느리면 수 분 이상 걸릴 수 있습니다. 기존 파일은 재사용하고, 다운로드가 완료된 파일만 최종 경로에 저장합니다. 데이터의 이용 조건은 [Dataset/README.md](../Dataset/README.md)를 따릅니다.

## Windows에서 열기

최초 준비 후 리포지토리의 `Launch.cmd`를 더블클릭합니다. 기본 WSL 배포판의 `~/.venvs/antiflood`에서 서버를 실행하고, 준비 상태를 확인한 뒤 Windows 브라우저로 [대시보드](http://127.0.0.1:8000)를 엽니다. 기본 WSL 배포판은 최초 준비를 수행한 Ubuntu여야 합니다.

서버가 이미 준비되어 있으면 같은 서버에 연결합니다. 실행 실패 시 표시되는 안내와 `outputs/logs/launcher.log`를 확인합니다. 포트 8000을 다른 프로그램이 사용 중이면 그 프로그램을 종료한 뒤 다시 엽니다.

Linux에서 직접 실행하려면 같은 가상환경에서 다음 명령을 사용합니다.

```bash
python -m antiflood.api
```

## 대시보드 사용

1. **새 계산 지역**을 고릅니다. 좁은 화면에서는 지도 제목 옆의 **실행 설정으로**를 누릅니다. 설정의 **지도로**를 누르면 지도로 돌아갑니다. 지역을 직접 정하려면 **지도에서 지정**을 누르고 사각형의 대각선 양끝을 선택합니다. **서울 전체**를 누르면 더 넓은 범위를 지도에서 볼 수 있습니다.
2. 지형과 강우 관측을 확인한 뒤 **강우 시나리오**를 고릅니다. 가정 배수율, CPU 스레드 수, 외곽 유출 설정은 **배수와 계산 조건**에서 바꿀 수 있습니다.
3. **계산 시작**을 누릅니다. 결과가 저장되면 지도 아래 시간 막대에서 시각을 고를 수 있습니다. 지도에서 지점을 선택하면 그 시각의 모의 수심을 볼 수 있습니다.
4. 새 조건으로 계산하려면 **초기화**를 누릅니다. **저장된 실행**을 펼치면 결과를 다시 열거나 설정을 재사용할 수 있습니다. 지도 아래에 **저장된 실행**이 표시되면 **현재 실행으로**를 눌러 복귀할 수 있습니다. 초기화와 서버 재시작 뒤에도 저장 파일은 남습니다.

실행 중에는 계산 조건이 고정됩니다. 다른 조건은 새로운 실행 ID로 계산합니다. 저장된 결과를 보면서 실시간 계산도 계속될 수 있으므로 현재 진행률과 저장 결과의 지도 시각을 구분해 확인합니다. Solar는 현재 실행의 최신 상태를 설명하며, 저장 기록을 볼 때는 질문 입력을 잠급니다.

## 범위와 가정

계산은 EPSG:5181의 30m 정사각형 격자와 100m Tile을 사용합니다. 서울 주변 경도 126.7–127.2°, 위도 37.4–37.72°에서 확보된 타일 안의 영역을 선택합니다. 이 사각형은 서울 행정 경계가 아닙니다. 필요한 DEM이 없거나 NoData가 포함된 곳, 관측소에서 12km를 넘는 곳은 실행 요청을 거절합니다. 한 번에 100만 셀 이하로 범위를 줄여야 하며, 사전 확인에서 셀 수와 대략적인 메모리 규모를 안내합니다.

각 셀에는 가장 가까운 관측소의 10분 누적 강우를 일정한 강도로 분배합니다. 관측이 빠진 구간은 시나리오를 나눠 보존하며, 위치 자료가 없는 관측소 1104는 제외합니다. 기본 강남역 시나리오는 2022년 8월 8일 00:00부터 9일 07:10까지 KST입니다. 다른 지역의 관측 누락에 따라 제공 구간이 달라질 수 있습니다.

기본 배수율 5mm/h는 가정값입니다. 외곽 유출 허용은 바로 바깥의 DEM 표고를 이용하고 외부 유입은 모의하지 않습니다. 닫힌 외곽에서는 물이 영역 밖으로 나가지 않습니다. 실제 하수관망과 도로·연석·지하 진입부는 모의하지 않으며, 관측 수심과의 일치도는 검증하지 않았습니다.

## 결과와 서버 설정

결과는 `outputs/frames/<실행 ID>/`에 저장됩니다. `run.json`은 실행 설정·격자·관측소·상태를 담고, `valid.npy`와 `gauge_map.npy`는 각 셀의 영역 및 관측소 정보를 담습니다. 시각별 `.npy` 수심(m), `.png` 지도 이미지, `.json` 수량과 UTC 시각은 같은 이름으로 연결됩니다. 화면은 KST로 표시합니다. 이전 버전의 결과에서 영역 마스크가 없으면 위치별 조회를 제공할 수 없습니다.

일반적인 시뮬레이션 설정은 대시보드에서 지정합니다. 서버 운영 설정은 선택적으로 `.env`에 둡니다.

| 환경 변수 | 용도 |
| --- | --- |
| `ANTIFLOOD_DATASET`, `ANTIFLOOD_OUTPUT` | 원본 데이터 및 결과 저장 경로 |
| `ANTIFLOOD_ENGINE` | 빌드된 계산 라이브러리 경로 |
| `ANTIFLOOD_PORT` | 수동 실행 시 포트. Windows 실행기는 8000 사용 |
| `ANTIFLOOD_FRAME_WAIT` | 프레임 발행 후 대기 시간. 기본 0.15초 |
| `UPSTAGE_API_KEY`, `UPSTAGE_MODEL` | 선택적인 Solar 기능. 기본 모델 `solar-mini4` |

기존 배수율 GeoTIFF 환경 변수는 서버의 초기 기본 격자에 적용됩니다. 웹 실행은 화면에서 지정한 균일 가정 배수율을 사용합니다. Solar 키가 없어도 계산과 지도 기능을 사용할 수 있습니다.

마지막 프레임의 누적 셀 갱신 횟수는 1,466,377,911회입니다. 이는 셀별 계산을 누적한 값이며 서로 다른 셀의 수가 아닙니다. 건조한 시각은 계산을 건너뛰고, 집중호우 때는 전체 유효 셀을 계산하며, 비가 그친 뒤에도 잔류 수심과 이웃 유입 가능성을 따라 계산하는 흐름을 설명할 수 있습니다. 이 실행만으로 속도 향상률을 주장하지 않습니다.

지형과 강우는 실제 자료이고, 배수율은 가정값이며 화면의 수심은 모의 결과입니다. 침수흔적도 비교 기능은 구현되지 않았고 실측 수심 정확도는 검증하지 않았습니다. Solar는 키가 없어 실제 응답을 확인하지 않았습니다. 서버 재시작 후 재열기는 이번 시연에서는 확인하지 않았으며, 사용자 선택에 따라 현재 서버를 유지했습니다. 페이지 새로고침 후 저장 기록 재열기는 확인했습니다.
