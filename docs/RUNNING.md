# 설치와 실행

## 최초 준비

Windows에서는 WSL Ubuntu에서 Python 3.11 이상과 CMake 3.20 이상, OpenMP 지원 C++ 컴파일러를 준비합니다. 지도에는 WebGL 2를 지원하는 브라우저가 필요합니다. 아래 명령은 리포지토리 루트에서 한 번 실행합니다.

```bash
sudo apt update
sudo apt install g++ cmake make python3 python3-venv ca-certificates
python3 -m venv ~/.venvs/antiflood
source ~/.venvs/antiflood/bin/activate
python -m pip install -e .
python -m antiflood.prepare
cmake -S engine -B build/engine-linux -DCMAKE_BUILD_TYPE=Release
cmake --build build/engine-linux
```

준비 명령은 서울시 강우 ZIP, EPSG:5181 관측소 위치, 빗물펌프장 위치, FABDEM의 N37E126과 N37E127 타일, 서울시 침수흔적도와 MapLibre 배포 파일을 내려받습니다. 기존 파일은 재사용합니다. 침수흔적도 다운로드가 실패하면 지도와 계산은 계속 사용할 수 있습니다. 데이터의 이용 조건은 [Dataset/README.md](../Dataset/README.md)를 따릅니다.

## Windows에서 열기

최초 준비 후 리포지토리의 `Launch.cmd`를 더블클릭합니다. 기본 WSL 배포판의 `~/.venvs/antiflood`에서 서버를 실행하고, 준비 상태를 확인한 뒤 Windows 브라우저로 [대시보드](http://127.0.0.1:8000)를 엽니다. 기본 WSL 배포판은 최초 준비를 수행한 Ubuntu여야 합니다.

서버가 이미 준비되어 있으면 같은 서버에 연결합니다. 실행 실패 시 표시되는 안내와 `outputs/logs/launcher.log`를 확인합니다. 포트 8000을 다른 프로그램이 사용 중이면 그 프로그램을 종료한 뒤 다시 엽니다.

Linux에서 직접 실행하려면 같은 가상환경에서 다음 명령을 사용합니다.

```bash
python -m antiflood.api
```

## 대시보드 사용

1. **실행 설정**을 펼칩니다. 기본 지역은 서울 전역입니다. 강남역, 여의도, 마포, 송파 또는 지도에서 직접 지정한 범위도 계산할 수 있습니다.
2. **강우 시나리오**, **계산 모드**, **배수 조건**을 고릅니다. 기본 모드인 **두 모드 비교**는 Reference를 먼저 계산한 다음 Streaming을 실행합니다. 같은 조건의 완료된 Reference가 있으면 바로 재사용합니다. 기본 배수 조건은 **시설 제원 기반 지역별 배수능력**입니다. 서울 밖 가정 배수율, CPU 스레드와 외곽 조건은 **세부 계산 조건**에서 바꿀 수 있습니다.
3. **계산 시작**을 누릅니다. 지도 왼쪽 패널에서 수심, 활성 Tile, 수심 오차, 침수흔적도, 배수능력, 관측소 강우를 바꿔 봅니다. 지도 아래 시간 막대와 시계열 차트로 두 결과의 같은 시각을 확인하고, 차트를 누르면 그 시각으로 이동합니다. 지도에서 지점을 고르면 수심, 배수능력, Tile의 강우와 Window 값, 수평 유동 계산 정책을 확인할 수 있습니다.
4. **저장된 실행**에서 결과를 열거나 설정을 재사용할 수 있습니다. 초기화와 서버 재시작 뒤에도 저장 파일은 남습니다. 실행 중에 저장 결과를 보는 경우 **현재 실행으로**를 눌러 돌아갑니다.

실행 중에는 계산 조건이 고정됩니다. 다른 조건은 새로운 실행 ID로 계산합니다. 저장된 결과를 보면서 실시간 계산도 계속될 수 있으므로 현재 진행률과 저장 결과의 지도 시각을 구분해 확인합니다. Solar는 현재 실행의 최신 상태를 설명하며, 저장 기록을 볼 때는 질문 입력을 잠급니다.

## 범위와 가정

계산은 EPSG:5181의 30m 격자와 100m Tile을 사용합니다. 기본 영역은 SGIS 서울시 경계와 격자 축마다 750m의 인접 지형을 포함합니다. 계산 영역과 행정경계는 지도에서 별도로 표시합니다. 사용자 지정 영역은 서울 주변 경도 126.7–127.2°, 위도 37.4–37.72° 범위에서 선택할 수 있습니다. 계산 배열은 최대 165만 셀입니다. DEM 결측이 있거나 유효 셀에서 가장 가까운 관측소까지 12km를 초과하면 실행을 거절합니다.

각 셀에는 가장 가까운 관측소의 10분 누적 강우를 일정한 강도로 분배합니다. 서울 전역에서 47개 관측소 자료가 모두 있는 연속 구간은 2022년 8월 8일 00:00부터 23:10까지 KST입니다. 강남역 주변에서는 9일 07:10까지 이어집니다. 지역에 따라 필요한 관측소가 달라지며, 결측이 있는 구간에서는 시나리오를 나눕니다.

기본 배수능력은 시설 제원으로 추정한 값입니다. 서울시 셀은 지선 하수관 설계 강우강도 78.7mm/h를 쓰고, 빗물펌프장 배수구역 근사 범위는 자치구별 펌프 용량으로 제한합니다. 서울 밖 셀에는 가정 배수율(기본 5mm/h)을 적용합니다. 산정 방법은 [시스템 아키텍처](ARCHITECTURE.md#유효-배수능력)에 있습니다. 실제 배수량이나 시설 가동 기록이 아니며, 균일 가정 배수율을 고르면 이전처럼 모든 셀에 같은 값을 씁니다. 외곽 유출 허용은 바로 바깥의 DEM 표고를 이용하고 외부 유입은 모의하지 않습니다. 닫힌 외곽에서는 물이 영역 밖으로 나가지 않습니다. 실제 하수관망과 도로·연석·지하 진입부는 모의하지 않으며, 관측 수심과의 일치도는 검증하지 않았습니다.

## 결과와 서버 설정

결과는 `outputs/frames/<실행 ID>/`에 저장됩니다. `run.json`에는 입력 지문, 계산 모드, 설정, 연결된 Reference, 실행 시간과 사건 최대 수심의 관측 기록 비교가 있습니다. 시각별 압축 `.npz`에는 수심과 Streaming Tile 상태가, 동명의 `.json`에는 계산 시각, 수량, 계산 시간과 비교 지표가 있습니다. `maximum.npz`는 셀별 사건 최대 수심, `drainage.npz`는 셀별 배수능력과 출처 구분입니다. 지도 PNG는 요청에 따라 생성합니다. 예전 `.npy`와 `.png` 실행도 다시 열 수 있습니다.

일반적인 시뮬레이션 설정은 대시보드에서 지정합니다. 서버 운영 설정은 선택적으로 `.env`에 둡니다.

| 환경 변수 | 용도 |
| --- | --- |
| `ANTIFLOOD_DATASET`, `ANTIFLOOD_OUTPUT` | 원본 데이터 및 결과 저장 경로 |
| `ANTIFLOOD_ENGINE` | 빌드된 계산 라이브러리 경로 |
| `ANTIFLOOD_PORT` | 수동 실행 시 포트. Windows 실행기는 8000 사용 |
| `ANTIFLOOD_FRAME_WAIT` | 프레임 발행 후 대기 시간. 기본 0.15초 |
| `UPSTAGE_API_KEY`, `UPSTAGE_MODEL` | 선택적인 Solar 기능. 기본 모델 `solar-mini4` |
| `ANTIFLOOD_DRAINAGE` | 서버 초기 격자의 배수 방식. `facility`(기본) 또는 `uniform` |

기존 배수율 GeoTIFF 환경 변수는 서버의 초기 기본 격자에 적용됩니다. 웹 실행은 화면에서 고른 배수 조건을 사용합니다. 시설 기반 배수에는 준비 명령이 내려받는 빗물펌프장 위치 파일(OA-21179)이 필요합니다. Solar 키가 없어도 계산과 지도 기능을 사용할 수 있습니다.

## 발표용 저장 결과

Windows에서 `Launch.cmd`를 열면 가장 최근에 저장한 서울 전역 비교가 자동으로 표시됩니다. 직접 열려면 **저장된 실행**에서 **서울 전역 / 비교 / 139개 (5186c8)** 항목을 고릅니다. 재계산 없이 공통 시간 막대로 두 지도를 재생할 수 있습니다.

- [Reference 실행](../outputs/frames/1f99a2fe01ab4182bac7c958bd61a629/run.json)
- [Streaming 실행과 비교](../outputs/frames/5186c8fe4264403b8a15c523bc366ac4/run.json)

2022년 8월 8일 00:00부터 23:10까지 KST의 서울시 강우 139구간을 계산했습니다. 47개 관측소를 사용했으며, 서울과 인접 지형의 유효 셀은 837,154개입니다. 동일한 노트북에서 4스레드, 가정 배수율 5mm/h, 외곽 유출 허용 조건으로 두 모드를 순차 실행했습니다.

| 측정값 | Reference | Streaming |
| --- | ---: | ---: |
| 계산 시간 | 148.87초 | 492.76초 |
| 수평 유동 계산 셀 수 (누적) | 23,003,317,612 | 15,673,224,158 |
| 갱신 지연 중앙값 | 0.25초 | 0.57초 |
| 결과 저장 시간 | 7.70초 | 8.54초 |
| 기록 폴리곤과 겹친 면적 비율 | 52.17% | 52.15% |

Streaming은 수평 유동 계산량을 31.87% 줄였고 실행 시간은 3.31배로 늘었습니다. 세 개 실제 강우 구간의 추가 프로파일에서 Tile 선택이 Streaming 계산 시간의 약 40%를 차지했습니다. 마지막 시각의 전체 RMSE는 12.70mm, 두 결과의 침수 영역 합집합 RMSE는 29.70mm, IoU는 99.20%입니다. 침수 기준은 수심 5cm입니다.

서버를 다시 시작한 뒤 Windows Edge에서 139개 저장 시각, 지도 확대 동기화, Timeline 재생, 활성 Tile, 수심 오차와 침수흔적도 레이어를 확인했습니다. 강남역 부근 지도에서 23:10의 한 Tile을 선택하면 현재 10분 강우 0mm, 60분 누적 9mm, 감쇠 점수 11.4mm와 감쇠 점수로 활성화된 이유를 확인할 수 있습니다.

침수흔적도에는 8월 9일 시작 기록도 포함됩니다. 기록과 겹치는 비율은 모의 기간의 최대 수심을 사용한 공간 비교이며, 기록 밖의 영역과 실제 관측 수심 정확도는 판단할 수 없습니다.
