# AntiFlood 프로젝트 개선 방향

2026년 11월 25일 사용자가 전달한 개선 방향을 구현과 검토에 필요한 항목으로 정리한 명세다. 자율 실행과 검증의 세부 규칙은 [사용자 실행 지침 원문](AUTONOMOUS_DEVELOPMENT.md)을 따른다. 기존 `DEVELOPMENT_SPEC.html`은 이전 선택적 영역 계산의 설계 기록이며, 충돌하는 요구사항은 이 명세로 대체한다. 이 문서는 목표이고, 현재 구현 상태는 `.ralph/STATE.md`와 실제 코드로 구분한다.

## 연구 질문과 범위

대규모 시공간 강우 데이터가 지속적으로 유입되는 상황에서, 입력에 의해 변화하는 서울 전역의 침수 상태를 제한된 계산 자원으로 얼마나 빠르게 갱신 가능한가?

빅데이터개론 프로젝트로서 대규모 시공간 입력 처리와 계산 자원 절약을 연구한다. 고정밀 침수 예측 모델 개발이 목적은 아니다. 서울 DEM과 기존 데이터셋, 30m 물리 격자, 100m Tile, WCA2D, C++와 OpenMP, Python, FastAPI, MapLibre, 배수능력 모델, 실행 및 저장 결과 조회, Reference 비교를 유지한다.

위험도에 따라 수평 유동을 계산하지 않는 정책을 제거한다. 서울 전역의 모든 유효 격자를 지속적인 계산 대상으로 유지하고, 상태 변화에 따라 지역별 계산 빈도를 조절한다. 강우, 배수, 유입과 유출을 임의로 생략하지 않는다. 비가 그친 뒤에도 물의 이동과 배수를 계산한다. 질량 보존, 비음수 수심, 유한한 결과와 수치 안정성을 지킨다. 공통 결과 시각에는 모든 지역이 같은 물리 시각까지 계산되어 있어야 한다.

## 입력과 강우 요약

원본 강우 자료를 보존하면서 10분 입력을 시간순으로 읽는다. 현재 구간의 처리가 끝나면 실행 중인 처리기에서 이전 입력의 참조를 제거한다. 전체 시나리오 강우 배열을 미리 적재하거나 처리한 입력을 누적해서는 안 된다. 시나리오 목록, 재생, 비교 조건 해시에서도 전체 이력을 보유하는지 확인한다. 결과 조회를 위해 저장한 관측 강우 기록은 실행 중 입력 이력과 구분한다.

실행 상태에는 현재 관측소별 강우, 감쇠 요약, 모든 셀의 현재 및 최대 수심, 지형과 배수 및 이웃 정보, Tile별 계산 주기와 물리 시각을 유지한다. 개별 과거 입력은 감쇠 가중합으로 요약한다. 새 입력마다 `decay = 0.8 * decay + rain`으로 갱신한다. 0.8은 기존 초기값이며 최적값으로 주장하지 않는다. 이 값은 계산 주기를 단축하는 보조 조건이고 실제 물을 줄이는 계수가 아니다.

정확한 최근 60분 합계가 필요한 기존 기능이 있는지 확인하고, 용도가 없으면 Sliding Window를 제거한다. 유지할 때는 그 기능에 한정한다. Data Stream Processing과 Decaying Window로 이력 저장 공간과 재탐색 비용을 줄이는 대신 처리기의 개별 과거 입력 조회와 상세 이력을 포기한다.

## 지역별 Adaptive Time Stepping

Tile은 계산 대상 선정 대신 지역 상태와 계산 주기를 관리한다. Tile 내부의 모든 30m 격자와 이웃 연결을 유지한다. 현재 강우와 감쇠 강우, 수심, 변화율, 인접 유량, 안정성 조건 중 필요한 최소한의 기준으로 주기를 정한다. 비가 없어도 유량이나 수심 변화가 크면 짧은 주기를 쓴다. 외부 유입과 급격한 변화에는 주기를 즉시 단축하거나 필요한 시점에 동기화한다.

주기는 소수의 이산 단계로 제한한다. 정수배 관계인 3.75, 7.5, 15초 등은 검토 예시이며 확정 설정이 아니다. Reference도 이미 최대 15초의 가변 주기를 쓰므로 더 짧게 계산하는 것만으로 절감이라 주장할 수 없다. 일부 지역이 공통 Reference 간격보다 긴 주기를 안전하게 사용하여 실제 물리 셀 연산 횟수를 줄여야 한다. 기존 15초 상한을 넘길 때는 안정성과 정확성 근거가 필요하다. 최종 상한은 강우 임계값이 아닌 물리 조건으로 제한한다.

서로 다른 주기의 경계에서도 donor에서 차감한 부피를 receiver에 정확히 한 번 반영한다. 누적 유량의 중복 반영, 미반영 물의 재유출, 서로 다른 시각의 상태 참조를 다룬다. 공통 동기화 시점에는 모든 지역의 물리 시각이 같아야 한다. 질량 보존만으로 적분 정확성을 판단하지 않고 Reference와 과정별 수심도 비교한다. 과거 유량에 시간 비율을 곱하는 방식은 비선형 WCA2D의 제한 조건과 호환되는지 먼저 검토한다.

임계값은 안정성 확인, 후보 2~3개 설정, 같은 조건의 Reference 비교 순으로 선정한다. 선정 입력과 최종 평가 입력은 가능한 한 구분한다. 사용자가 정하지 않은 수심 오차 한도를 임의의 합격 기준으로 확정하지 않는다. 실제 시간과 오차를 제시한다. 공간 해상도와 물의 연속성을 유지하면서 완만한 지역의 시간적 정밀도를 일부 포기하는 것이 핵심 trade-off다.

엔진 전체를 교체해야 하거나 관리 비용이 이점보다 큰 근본 문제가 있으면 작동하는 Reference와 전체 영역 동기 계산을 보존한다. 선택적 제외로 회귀하거나 다른 근사법으로 연구 방향을 바꾸지 않고 BLOCKED로 근거와 필요한 판단을 보고한다.

## 기존 개념의 재사용과 병렬 처리

| 개념 | 적용 위치와 효과 | 포기하는 정보 또는 비용 |
| --- | --- | --- |
| Pregel과 유사한 BSP | 30m 셀을 정점, 이웃을 간선, 수심을 상태, 전달 부피를 메시지로 보는 동기적 반복 | 단계별 동기화 비용 |
| Sparse Representation | 동서남북 이웃만 저장하여 연결 공간을 O(N²)에서 O(N)으로 제한 | 직접 상호작용하지 않는 셀 쌍의 연결 |
| Temporal Sampling | 물리는 계속 계산하고 10분마다 모든 셀의 수심을 저장, 최대 수심은 지속 갱신 | 저장 시각 사이 상세 수심 |
| Parallel Processing | 기존 OpenMP 정적 분배로 셀 연산 병렬화 | 추가 CPU 자원과 병렬 오버헤드 |

실제 Pregel 프레임워크를 도입하지 않는다. Temporal Sampling은 강의의 무작위 및 해시 샘플링을 시간축에 응용한 것이고, Adaptive Time Stepping은 강의의 특정 알고리즘을 그대로 구현한 것이 아니다. 기존 개념에 이름만 붙여 새 구현이라고 설명하지 않는다.

4스레드 Reference와 같은 자원의 개선 방식을 먼저 비교한다. 사용 가능한 추가 스레드 설정 1~2개로 병렬 효과를 따로 확인한다. 동적 부하 분산, 자동 튜닝, 새로운 분산 프레임워크, 인프라, DB, 실시간 관측 API, ML, 물리 모델 교체, 클라우드 배포는 범위 밖이다.

## 실행 흐름과 평가

새 입력 → 감쇠 요약 → Tile별 주기 결정 → WCA2D와 OpenMP 다중 주기 계산 → 보존적 경계 전달 → 상태 변화에 따른 주기 조정 → 공통 시각 동기화 → 전체 수심 저장 및 지도 갱신 → 처리 입력 참조 폐기 → 다음 입력 순으로 실행한다.

같은 강우, DEM, 초기 상태, 배수, 경계, 물리 커널, CPU 자원으로 Reference와 비교한다. 전체 및 입력별 계산 시간, 실제 물리 셀 연산 횟수, CPU 시간과 사용량, 최대 메모리, 저장량, 과정별 및 최종 RMSE와 IoU, 질량 오차를 측정한다. 입력 도착 주기인 600초 안에 처리를 마치는지도 확인한다. 저장과 시각화 시간은 물리 계산 시간과 구분한다. RMSE와 IoU는 Reference 일치도이며 실측 정확도가 아니다. 이전 선택적 방식의 성능을 새 알고리즘 성능으로 재사용하지 않는다.

작은 격자의 안전 조건, 짧은 실데이터 기능, 구현 확정 후 서울 전역 최종 비교 순으로 검증한다. 가능하면 최종 조건별 3회의 중앙값과 범위를 기록한다. 실험 선정과 예산, 브라우저 검증, 고정 README 구조, 아키텍처 이미지 품질, 기존 사용자 흐름과 결과 호환은 사용자 실행 지침을 따른다. 미구현 기능이나 측정하지 않은 개선은 완료로 쓰지 않는다.

개발 순서는 전체 격자 지속 계산, 입력 소유 및 감쇠 요약, 지역별 주기와 경계 안전성, 성능 및 오차, 스레드 비교, API와 대시보드, 문서 갱신이다. 완료 조건은 `.ralph/GOAL.md`의 G01–G16으로 고정한다.
